# ADR-0011 — Countries are replayable recipes, not alternate engines

**Status:** Accepted · **Date:** 2026-08-08

## Context

The original procedural mode changed only a name, a narrow population range, development,
openness, and four capacities. Every draw inherited Meridia's sector mix, age shape, debt,
reserves, credit stock, and constitution. That produced cosmetic variety and repeatedly tested
the same small neighborhood of state space.

Country selection also happened after the decision had effectively been made: the UI generated
a random country on first load. There was no stable scenario id for a player or the batch runner
to request, and therefore no useful cross-country balance matrix.

## Decision

Countries are immutable `CountryParams` generated by a versioned recipe catalogue. Five curated
recipes describe materially different 1946 settlements; a procedural recipe chooses one of the
same bounded archetypes and jitters it deterministically from the game seed.

`CountryParams.structure` adds normalized sector output, employment, and capital multipliers;
opening debt, credit, and reserve stocks; and inherited institution stocks. Sector multipliers
change composition while `init` continues to derive scale from population and development. The
opening budget still self-calibrates from the tax base. No country owns a pipeline fork, a hidden
step, or a post-init state mutation.

Saves continue to embed the fully materialized parameter vector. A future recipe rebalance can
change new games without changing an old save's replay. The scenario id is routing metadata for
the worker and runner, not an additional source of truth.

The batch runner retains its historical baseline by default, accepts `--country <id>` for a
scenario, and accepts `--country all`; `all` distributes runs evenly over the curated catalogue
and procedural generator and prints a per-country stability/balance matrix.

## Alternatives considered

- **Separate pipeline or constants per country.** Rejected: it creates several economies that
  merely share source files, makes every balance fix conditional, and widens the economy/politics
  seam.
- **Store only `(countryId, seed)` in saves.** Smaller, but recipe changes would rewrite old
  history. Embedding materialized params is the existing replay contract and is worth the bytes.
- **Arbitrary state snapshots as scenarios.** Powerful for debugging, but violates ADR-0001 and
  can manufacture states the engine could never reach.
- **Keep countries as fixtures.** Useful for tests, not a product contract. The UI worker and
  runner would each need their own catalogue and would drift.

## Consequences

**Good:** country choice changes economic and political terrain; generated scenarios are bounded,
validated, reproducible, and directly available to stress tests; Meridia remains the exact golden
baseline; old saves without `structure` remain valid.

**Bad:** the parameter contract is wider; curated openings need balance review as a matrix; recipe
metadata includes a small amount of player-facing prose in the otherwise mechanical engine
package; schema 13 golden hashes move because the schema stamp changes.
